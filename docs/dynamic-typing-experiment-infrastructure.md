# Инфраструктура трёхстороннего эксперимента с динамической типизацией

Статус: инфраструктура и контракт готовы; модельный агент типизации, его системные
инструкции и правила принятия решения намеренно **не реализованы**. Научная идея
описана в [исходном алгоритме](../../global_docs_SMILES/research/DYNAMIC_ENTITY_TYPING_ALGORITHM.md).
Эта страница определяет границу, в которую будущая реализация должна быть подключена
без изменения KGGen, GraphEval и базового HalluGraph.

## Цель сравнения

Для одного неизменяемого no-gold объекта RAGTruth `(контекст, вопрос, ответ)` фреймворк
запускает три разных варианта:

| Вариант | Семейство метода | Что получает |
|---|---|---|
| `grapheval_kggen_shared_answer_*` | GraphEval | Общий `G_answer` и исходный контекст для NLI |
| `hallugraph_untyped_shared_kggen_*` | базовый HalluGraph | Общие `G_context`, `G_query`, `G_answer` |
| `hallugraph_dynamic_types_*` | HalluGraph с типизацией | Те же три графа и отдельную аннотацию типов |

`G_context`, `G_query` и `G_answer` извлекаются **ровно один раз** через KGGen до
вызова любого детектора. Типизация ничего не переписывает в этих графах: она создаёт
отдельный слой аннотаций. Поэтому разница между двумя вариантами HalluGraph позднее
будет относиться к типизации, а не к различной экстракции графа.

```text
no-gold RAGTruth
       |
       v
общий запечатанный набор KGGen: (G_context, G_query, G_answer)
       |                 |                         |
       |                 |                         +--> GraphEval
       |                 +----------------------------> HalluGraph B0
       v
реестр типов только из context + query, затем аннотация answer
       |
       +----------------------------------------------> HalluGraph B1
```

## Неизменяемый набор графов и кэш

`experiments.shared_graphs.SharedKGGraphProvider.prepare_instance()` создаёт
`SharedGraphBundle`. В нём хранятся идентификатор набора, контрольная сумма и три
`SharedGraphArtifact`. Ссылка на набор и все три идентификатора графов попадают в
каждую строку предсказания. Полный индекс записывается в
`shared_graphs/bundles.jsonl` внутри архива запуска.

Провайдер уже поддерживает источники `GraphCacheSource`, в том числе исторический
кэш `hallu-kg-cache-v2`, и режим `cache_only`. Для DataSphere путь к кэшу передаётся
конфигурацией запуска как источник кэша, а не вшивается в код. Перед реальным
воспроизведением надо вызвать `preflight(..., roles=("context", "query", "response"))`:
пропуск хотя бы одного графа не должен незаметно переключать запуск на обращение к
модели. Совместимость со старым ключом кэша допускается только если она явно
заявлена read-only источником.

Подробности прежнего двухметодного варианта сохранены в
[controlled shared-KGGen track](shared-kggen-controlled-track.md). Новый трёхсторонний
вариант расширяет его до общего набора всех трёх графов, не меняя сам алгоритм KGGen.

## Контракт типизации

Контракт находится в `experiments/dynamic_typing.py`. Он намеренно не зависит от
промпта, клиента модели, сети или внешней онтологии.

1. `SourceTypingInput` содержит только `context`, `query`, их графы и идентификатор
   набора. По нему `DynamicTypingProvider.build_source_registry()` возвращает
   неизменяемый `SourceTypeRegistry`.
2. Реестр помечен `frozen=True`. Он может содержать только категории, выведенные из
   контекста и вопроса. Голд-меток RAGTruth, ответа и данных других источников в
   этот шаг не передаётся.
3. `AnswerTypingInput` содержит ответ и `G_answer`. Метод
   `annotate_answer()` должен присвоить узлу одну из уже существующих категорий или
   явно воздержаться (`assignment_status="unknown"`). Он не имеет права расширить
   реестр категорией, увиденной только в ответе.
4. Результат `TypeAnnotationBundle` ссылается одновременно на реестр и общий набор
   графов. Он сохраняется в `typing/type_annotation_bundles.jsonl`; сами реестры — в
   `typing/type_registries.jsonl`.

Одна строка `TypeAssignment` содержит стабильный временный `node_id`, поверхность
сущности, нормализованную форму, категорию либо `null`, статус, способ присвоения и
уверенность. До появления богатого внутреннего представления графа `node_id`
детерминированно получается из идентификатора графа и текста сущности. Замена этого
механизма допустима только с версией контракта и миграцией архивной схемы.

Будущий агент обязан реализовать протокол `DynamicTypingProvider` и должен:

- принимать только эти два no-gold входа и не читать gold-поля;
- выпускать только категории замороженного реестра либо `unknown`;
- фиксировать имя/версию модели, версию инструкций, контрольную сумму входа,
  решение и причину воздержания в собственных архивных строках;
- не модифицировать `SharedGraphBundle`, `Graph` или запись базового предсказания;
- преобразовывать сетевые ошибки в явный статус ошибки, а не в тип или оценку.

Конкретные инструкции агенту, модель, формат ответа модели, словарь категорий и
способ включения типов в метрику — отдельная будущая задача. Этот документ не
предрешает их.

## Текущая заглушка

`UnknownTypeProvider` — основная проверочная реализация. Она присваивает каждому
узлу `unknown`, создаёт те же архивные записи, но не меняет оценку HalluGraph.
`TypedHalluGraphAdapter` сначала создаёт аннотации, затем вызывает базовый адаптер
без изменения его входа и добавляет ссылку на типизацию в `components` и
`artifact_refs`.

Это даёт проверяемый инвариант: в тестовом запуске `B1_unknown.raw_score ==
B0.raw_score` и одинаковы помеченные единицы. Равенство не является гипотезой о
будущем методе; это защита инфраструктуры от скрытого изменения базовой линии.

## Идентичность вариантов и архив

`method` обозначает семейство (`grapheval` или `hallugraph`), а `variant` — точную
конфигурацию. `method_run_id` и `prediction_id` строятся по варианту; поэтому два
варианта HalluGraph не перезаписывают друг друга при продолжении запуска.

`predictions/paired_predictions.jsonl` теперь является матрицей сравнения: в нём
есть словари `variant_prediction_ids`, `variant_statuses`, `variant_scores` и
признаки общей связки графов. Для включения записи в основной трёхсторонний анализ
все три статуса должны быть `ok`, а `all_variants_same_graph_bundle` — `true`.
Классический двухметодный признак сохраняется только для обратной совместимости и
не заменяет эту проверку.

`prediction_seal.json` содержит перечень вариантов и контрольные суммы графового
индекса, набора графов и обоих файлов типизации. Объединять предсказания с gold
можно лишь после запечатывания, как требуют протоколы эксперимента.

## Проверка без сети

`tests/experiments/test_three_way_dynamic_typing.py` запускает один синтетический
no-gold объект с FakeKGGen/FakeNLI и доказывает следующее:

1. в холодном проходе существует ровно один набор и три общих графа;
2. все три варианта ссылаются на один и тот же набор;
3. заглушка `unknown` сохраняет результат базового HalluGraph;
4. архив содержит реестр, аннотации и проходит проверку контрольных сумм;
5. второй проход в `cache_only` не вызывает KGGen.

Запуск:

```bash
python -m pytest -c pytest.framework.ini -q tests/experiments/test_three_way_dynamic_typing.py
```

Это проверка проводки, а не экспериментальная метрика и не запуск DataSphere.
