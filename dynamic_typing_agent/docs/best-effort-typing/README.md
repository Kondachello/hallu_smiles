> Папка документирует изменение алгоритма типизации сущностей (`quality_workflow` v3 → **v4-best-effort**)

## Кратко (TL;DR)

**Проблема.** Если NLI (HHEM) не подтверждал ни одного предложенного типа, сущность откатывалась
к структурному корню `T-ENTITY` (метка `entity`) — бесполезному служебному типу. Из-за того, что на
первом уровне иерархии родитель — это `entity`, сущности массово получали неинформативный тип.

**Решение (v4-best-effort).**
1. Цикл до `max_entity_attempts` гипотез (**дефолт 2 → 3**, настраивается).
2. При «слабом» NLI (только neutral) — переспрос новой гипотезы (`retry_on_neutral`, дефолт `true`),
   чтобы попытаться получить source-entailed тип.
3. После исчерпания попыток — вместо корня берётся **самый правдоподобный по NLI** кандидат из всех
   проверенных за все попытки: ранжирование `entailed > neutral > contradicted`, затем по силе
   доказательства. Корень `entity` остаётся **только если модель вообще не предложила ни одного типа**.
4. Best-effort выбор помечается `evidence_level=unknown`, получает явную причину (`reason`) и событие
   `type_best_effort_fallback` в трейсе — низкая уверенность остаётся видимой и аудируемой.

**Проверка.** 57 оффлайн-тестов зелёные; live-прогон на 20 примерах (gateway LLM + локальный HHEM):
19/20 успешно, типы осмысленные (`commercial bank`, `financial institution`, `reference implementation`,
`managed database service`…), best-effort сработал в 4 местах вместо `entity`, голым `entity`
схлопнулись лишь 2 назначения (случаи «модель не предложила ничего»).
